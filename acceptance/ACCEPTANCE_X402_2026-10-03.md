## Gates

1. **Unpaid request returns 402** — PASS. Live server returned HTTP 402 with
   `payment-required` header: exact / eip155:84532 / USDC / 0.10 /
   payTo 0x2615e1327C092421f389Bb2c992d8C28b9C2639D.
2. **Payment requirement correct** — PASS (asset, network, amount, seller all correct).
3. **Buyer signs x402 authorization** — PASS. EIP-3009 authorization signed by buyer;
   signature verified locally (recovers to buyer address).
4. **Facilitator verifies and settles** — PARTIAL / DEVIATION. The x402.org facilitator
   was reached and understood the v1 payload, but returned
   `invalid_exact_evm_missing_eip712_domain`: the Base Sepolia testnet USDC contract
   does not implement EIP-5267 `eip712Domain()` (call reverts), so the facilitator
   cannot construct the signing domain for this token. Settlement was therefore
   executed directly on-chain by submitting the buyer's signed EIP-3009
   authorization — the same primitive the facilitator would have submitted.
   The kit's `FacilitatorVerifier` also posts `{payload, requirements}` while the
   x402.org facilitator expects `{paymentPayload, paymentRequirements}`, and expects
   network `base-sepolia` (not `eip155:84532`) for v1 — interop notes for the kit.
5. **Resource released** — NOT DEMONSTRATED via the kit server (its verifier depends on
   the facilitator, per gate 4). The 402 challenge/response cycle itself was live.
6. **Transaction confirmed on Base Sepolia** — PASS. Both transactions status=1,
   Transfer events verified via public RPC and Basescan.
